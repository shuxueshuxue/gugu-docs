The Search API lets you query all content in your Gugu workspace using full-text search. It supports filtering by content type, tag, and date range, giving you precise control over what results you surface. Responses are ranked by relevance score so the most pertinent items always appear first. All requests require a valid Bearer token in the `Authorization` header.

---

## Search content

Performs a full-text search across your workspace and returns ranked, paginated results.

```text
GET /v1/search
```

### Query parameters

<ParamField query="q" type="string" required>
  The search query string. Supports phrase matching and boolean operators — see [Query syntax](#query-syntax) below.
</ParamField>

<ParamField query="type" type="string">
  Filter results to a specific content type (e.g. `article`, `note`).
</ParamField>

<ParamField query="tag" type="string">
  Filter results to items that include this tag.
</ParamField>

<ParamField query="from_date" type="string">
  Return only results created on or after this date. Accepts an ISO 8601 date-time string (e.g. `2024-01-01T00:00:00Z`).
</ParamField>

<ParamField query="to_date" type="string">
  Return only results created on or before this date. Accepts an ISO 8601 date-time string (e.g. `2024-12-31T23:59:59Z`).
</ParamField>

<ParamField query="page" type="integer">
  The page number to retrieve. Defaults to `1`.
</ParamField>

<ParamField query="per_page" type="integer">
  Number of results to return per page. Defaults to `10`, maximum `50`.
</ParamField>

### curl example

```bash
curl "https://api.gugu.app/v1/search?q=project+roadmap&tag=important&per_page=20" \
  -H "Authorization: Bearer YOUR_API_KEY"
```

### Response fields

<ResponseField name="data" type="array">
  An array of search result objects, ordered by relevance score (highest first).

  <Expandable title="result object fields">
    <ResponseField name="data[].id" type="string">
      Unique identifier of the matching content item.
    </ResponseField>

    <ResponseField name="data[].title" type="string">
      Title of the matching content item.
    </ResponseField>

    <ResponseField name="data[].excerpt" type="string">
      A short snippet from the content body with the matching terms highlighted using `<mark>` tags.
    </ResponseField>

    <ResponseField name="data[].score" type="number">
      Relevance score assigned by the search engine. Higher values indicate a closer match.
    </ResponseField>

    <ResponseField name="data[].type" type="string">
      The content type of the result (e.g. `article`, `note`).
    </ResponseField>

    <ResponseField name="data[].created_at" type="string">
      ISO 8601 timestamp of when the item was created.
    </ResponseField>

    <ResponseField name="data[].tags" type="array">
      Tags associated with the content item.
    </ResponseField>
  </Expandable>
</ResponseField>

<ResponseField name="meta" type="object">
  Pagination and query metadata.

  <Expandable title="meta fields">
    <ResponseField name="meta.total" type="integer">
      Total number of results matching the query.
    </ResponseField>

    <ResponseField name="meta.page" type="integer">
      The current page number.
    </ResponseField>

    <ResponseField name="meta.per_page" type="integer">
      The number of results returned per page.
    </ResponseField>

    <ResponseField name="meta.query" type="string">
      The search query string as received by the API, after normalization.
    </ResponseField>
  </Expandable>
</ResponseField>

## Query syntax

The `q` parameter supports a rich query syntax that gives you fine-grained control over what the search engine matches.

### Phrase matching

Wrap multiple words in double quotes to search for an exact phrase rather than individual keywords.

```text
"project roadmap"
```

### Boolean operators

Combine terms with `AND`, `OR`, and `NOT` to build compound queries. Operators must be uppercase.

| Operator | Example | Behaviour |
|----------|---------|-----------|
| `AND` | `roadmap AND Q3` | Both terms must be present. |
| `OR` | `roadmap OR timeline` | Either term may be present. |
| `NOT` | `roadmap NOT draft` | The first term must be present; the second must not. |

### Combining operators

You can mix operators and phrases in a single query:

```text
"project roadmap" AND (Q3 OR Q4) NOT archived
```

<Note>
  When you include multiple terms without an explicit operator, the search engine defaults to `AND` — all terms must appear somewhere in the document.
</Note>

## SDK examples

<CodeGroup>

```javascript JavaScript
const results = await gugu.search('project roadmap', {
  tag: 'important',
  per_page: 20
});
```

```python Python
results = gugu.search('project roadmap', tag='important', per_page=20)
```

</CodeGroup>

<Tip>
  Use the `from_date` and `to_date` parameters together to narrow searches to a specific sprint, quarter, or release window.
</Tip>
