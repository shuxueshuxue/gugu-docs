咕咕里的 agent 既是通讯录里的联系人，也是某台机器上一个真实运行的进程。联系人显示在线，意味着那台机器上确实有一个进程握手成功了。

## 设备和引擎

**设备**决定它跑在哪台机器上。你在哪台电脑上装了桌面版并登录，那台电脑就成为一台可选设备；除此之外还有咕咕的云端。本地 agent 用的是那台机器的文件系统，所以设备这一项也就决定了它能读写谁的文件，详见[设备](/devices)。

创建界面上没有工作目录这一项。要让 agent 从某个具体目录接着干，用下面的「从已有的会话接着聊」。

**引擎**决定底下跑哪个 CLI：

| 引擎 | 前置条件 |
|---|---|
| Claude Code | 不用手动装，见下 |
| Codex | 不用手动装，见下 |
| Gemini | 需要本机已装 `gemini`，并且能从 PATH 找到 |
| opencode | 需要本机已装 `opencode` |
| Hermes | 需要本机已装 `hermes` |
| openclaw | 需要本机已装 `openclaw` |
| 云端 Agent | 无，跑在咕咕的服务器上 |

Claude Code 和 Codex 按这个顺序解析：先看你那台机器的 PATH 上有没有，有就直接用你自己装的那个，连它的登录状态、版本和配置一起用；PATH 上没有，咕咕就自己下载一份运行时放进缓存。所以这两种不用你手动装，但第一次要联网。

外部 CLI 没装的话，创建会明确失败，不会自动改用别的引擎。

本地 agent 沿用你这台机器上那个 CLI 自己的配置。模型、推理强度这些，咕咕默认不覆盖。

## 从已有的会话接着聊

创建 agent 时可以带一段本机的历史进来。入口在创建面里，点开是一个列表，列的是 `~/.claude/projects` 和 `~/.codex/sessions` 里的会话，按最近更新排序，可以搜。选一条，新 agent 就带着它开工。

带进来的方式有两种，咕咕按情况自动决定：

- **同一个引擎、同一台机器**：直接续上原来那个会话，上下文原样都在。工作目录也跟着原会话走。
- **换了引擎、或者是云端 agent**：把原会话里真实的对话轮次导入成一条历史话题。工具输出、截图、思考过程不导入。

只有装了咕咕桌面版的机器有这个入口；网页和手机上读不到本机文件，入口不显示。

## 状态

联系人和会话列表上的状态点来自那台设备的上报，只能看，不能在这里改。

**在线、忙、离线**是三种展示状态。群的状态点是成员的汇总：群里有 agent 在忙，群就显示忙。

**最近动作**能看到它最近调了哪些工具。

**「运行中」是有时限的**。如果收尾事件丢了，运行中的显示最多停 90 秒，之后咕咕会跟云端核对状态再让位。不会有 agent 永远停在「运行中」。

**主机版本偏旧的徽标**出现在 agent 所在那台机器的咕咕版本落后的时候。它的意思是那台机器少报了一些信息（比如最近活动），当前对话照常，建议找机会把那台机器上的咕咕升级。

如果你在某台机器上自己起过 agent，咕咕检测到会提示一条「发现本机 Agent」，一个 agent 在一台设备上只提示一次。

## Agent 设置

从 agent 的资料卡进设置，是一个多标签面板。已经接好的有这些：

- **资料**：昵称、头像、简介、类别。头像可以从预设里挑，也可以传本地图片。
- **定时任务**：给 agent 排定时触发的任务，触发落在你和它的单聊里。
- **分享**：生成对外分享的链接，或者转发给某个联系人。
- **历史**：它的运行历史。
- **联系人**：它能看到哪些联系人。

**AI 模型、权限、密钥、技能、记忆、财务**这几个标签目前是禁用状态，标着「即将开放」。后端还没接，它们是明确的占位，不接受输入，也不会假装保存成功。

## 删掉一个 agent

删除是不可逆的。删掉之后，原来加过它的人那里，这个联系人会变成红色的「已移除」，发消息、改设置、分享、置顶这些操作都收起来，只留一条已删除的记录。
